# 03 — ICP, Personas & Buyer Journey

## ICP

### Primary segment

Mid-market e-commerce brands with:
- 500–10,000 SKUs
- Multiple sales channels
- Small-to-mid-sized creative teams
- Frequent launches / catalog refreshes
- Existing PIM, DAM, CMS or marketplace workflows

### Trigger events

- SKU count expands
- A new marketplace is added
- A seasonal campaign launches
- Creative teams become a bottleneck
- Regional catalog variants multiply
- A brand wants to increase creative testing

## Persona 1 — Economic buyer

### Head of E-commerce

**Goal:** Increase merchandising velocity without proportionally increasing operating cost.

**Pain:** Creative production slows launches.

**Question:** "Will this improve the speed and economics of getting products live?"

**Message:**  
> Increase visual production capacity without adding a new production queue.

## Persona 2 — Champion

### Creative Operations Lead

**Goal:** Keep output consistent while handling increasing volume.

**Pain:** Repetitive editing, resizing, versioning and review.

**Question:** "Will this actually reduce work—or create another tool I have to manage?"

**Message:**  
> Define the rules once. Reuse them across the catalog.

## Persona 3 — Daily user

### Digital Merchandiser

**Goal:** Get products live with correct imagery.

**Pain:** Waiting for assets and fixing channel-specific requirements.

**Question:** "Can I get the exact formats I need without going back to creative?"

**Message:**  
> Turn one source image into channel-ready assets.

## Buyer journey

| Stage | Buyer thought | PMM job | Asset |
|---|---|---|---|
| Problem unaware | "Why are launches slow?" | Surface cost of production bottlenecks | Benchmark content |
| Problem aware | "Creative is holding us back." | Quantify workflow friction | ROI calculator |
| Solution aware | "Could AI solve this?" | Explain workflow vs generation | Explainer |
| Evaluation | "Which vendor fits our stack?" | Differentiate | Comparison page |
| Proof | "Will it preserve our product?" | Reduce risk | Demo + sample outputs |
| Purchase | "Can we operationalize this?" | Enable champion | Pilot plan |
| Expansion | "Can we use this across markets?" | Create new use cases | Expansion playbook |

## Activation hypothesis

The account is **activated** when it has:

> Uploaded 10+ products + defined a brand rule set + generated one approved multi-channel asset set.

That is more meaningful than a generic "account created" event because it represents the product's core value loop.
